# ロトカ＝ヴォルテラ比較シミュレーター

学校で、個体ルールから生じる生態系の変動とロトカ＝ヴォルテラ（LV）モデルとの差を観察する教材です。箱庭の個体数をLVの値へ補正する処理はありません。

## 起動・配布

1. GitHubの「Code → Download ZIP」で取得し、ZIPを展開します。
2. 展開したフォルダの `index.html` をブラウザで開きます。
3. 別のPCへは、`index.html` と `script.js` を同じフォルダに入れたままコピーします。

インターネット接続、インストール、ビルド、Node.js、Python、Webサーバーは不要です。HTML/CSSと通常のJavaScript、Canvasだけを使用し、外部ライブラリやCDNを読み込みません。ZIPの中から直接開かず、必ず展開してください。ブラウザのJavaScriptは有効にしてください。

Codespacesの転送ポートは開発時のプレビュー用であり、配布先では不要です。

## 操作

- **×1 / ×3 / ×5**：箱庭とLVの両方に同じ時間倍率を適用します。数値計算の時間刻みは変えません。
- **リスタート**：現在の能力設定・適用済みLV係数・速度を保ち、個体・配置・体力・繁殖待ち時間・経過時間・LV値・履歴を初期化します。位置は再抽選されます。
- **全リセット**：上記に加え、能力設定・LV係数と入力欄を初期値へ、速度を×1へ戻します。
- **能力設定を戻す**：能力倍率と探索距離だけを初期値へ戻します。
- **現在数から比較し直す**：入力したLV係数を適用し、その時点の箱庭の個体数からLV計算と記録を再開します。箱庭の状態と経過時間は保持します。

LV係数は入力だけでは適用されません。「現在数から比較し直す」で適用してください。能力倍率は即時反映されます。

## 計算とグラフ

箱庭は移動、空腹時の餌探索、捕食、体力消費による死亡、確率的な繁殖を個体ごとに処理します。初期配置は草120株、被食者40匹、捕食者2匹です。草は初期配置も追加生成もフィールド全体のランダムな位置に配置します。追加生成の確率は1/60シミュレーション秒ごとに4%（従来の半分）で、草が残り、上限200株未満の場合に発生します。絶滅後の個体や草は自動補充しません。

LVは独立して次を4次ルンゲ＝クッタ法で計算します。

- dx/dt = αx − βxy
- dy/dt = δxy − γy
- x：被食者、y：捕食者

開始時・リスタート時は、箱庭とLVを同じ初期個体数から始めます。両者を共通の1/60シミュレーション秒刻みで進め、1シミュレーション秒ごとに個体数を記録します。

同一グラフに、青実線＝箱庭の被食者、赤実線＝箱庭の捕食者、青破線＝LVの被食者、赤破線＝LVの捕食者を表示します。履歴は最大601点（直近600シミュレーション秒）です。ページを閉じると記録は失われます。

初期LV係数は α=0.06、β=0.02、δ=0.01、γ=0.12。比較用の仮設定で、箱庭の能力倍率との自動対応や推定はありません。LVには草・空腹・位置・探索行動が含まれず、LVの個体数は連続量です。一致の程度や違いが観察対象です。初期設定は恒久的な共存を保証しません。

## 負荷・画面・保守

非表示タブでは時間を止め、戻った際のまとめ計算を避けます。描画はブラウザの描画周期、グラフ更新は記録時とサイズ変更時に行います。履歴点数とグラフの描画解像度に上限があります。

×5では計算負荷も増えます。処理が大幅に遅れた際は追いつき計算を制限するため、実時間に対する倍率は下がり得ますが、箱庭とLVのシミュレーション時間は同期します。動物数に上限はなく、設定によって個体数が増えると負荷も増えます。古いPCでは×1と初期設定から確認してください。

広い画面では左に箱庭・右に操作盤・下にグラフを配置します。狭い画面や大きな表示倍率では、操作を隠さず縦に並べるためスクロールが必要です。表示サイズ変更で箱庭の内部座標800×600は変わりません。

LVの数値が非有限・負値・計算上限を超えた場合はLV計算を止めて画面に通知し、箱庭を継続します。係数を見直して比較を再開できます。

依存関係を少なくして長期保存しやすくしていますが、将来のブラウザで10年以上の動作を保証するものではありません。配布したフォルダを版ごとに保管してください。
